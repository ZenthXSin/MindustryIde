# 混淆（Obfuscation）

> 主题：概念说明

## 定义

**混淆**是指通过改写名称、结构或控制流程，让代码、数据或文本变得更难被直接理解的技术。

常见目标：
- **提高逆向分析难度**
- **隐藏实现细节**
- **降低被直接复制或篡改的风险**

## 常见形式

1. **标识符混淆**
   - 把类名、方法名、变量名改成无意义短名。
   - 例如：`PlayerManager` → `a`。

2. **控制流混淆**
   - 改写 `if / for / switch` 结构，让逻辑看起来更复杂。

3. **字符串混淆**
   - 把明文字符串编码、加密或拆分，运行时再还原。

4. **数据混淆**
   - 改变数据存储方式，增加分析成本。

## 典型用途

- 软件保护
- 反逆向
- 反静态分析
- 代码压缩中的名称缩短

## 优点

- 能增加阅读和分析成本
- 可降低部分源码泄露后的可读性
- 在某些场景下能提升保护强度

## 缺点

- 影响调试和维护
- 可能降低性能
- 不能真正“绝对防破解”
- 复杂混淆会增加崩溃排查难度

## 简单理解

可以把混淆理解成：**“把原本好懂的东西，故意变得不那么好懂。”**

## 例子

```js
// 混淆前
function addScore(score, bonus) {
  return score + bonus;
}

// 混淆后
function a(b, c) {
  return b + c;
}
```

## 备注

在安全领域里，**混淆**和**加密**不是一回事：
- **混淆**：主要目的是让人难读
- **加密**：主要目的是让没有密钥的人无法还原
