# Persistent Memory Policy

> Source: conversation-driven policy update

Persistent memory should keep only broad directions and normalized operating rules. Specific facts, examples, inventories, and project details should be moved into the knowledge base.

## What stays in memory

- High-level task priorities
- Stable interaction preferences
- Reusable output and execution conventions
- Long-lived project rules that must be applied consistently

## What moves to knowledge

- Detailed technical facts
- Project-specific inventories
- Examples, edge cases, and implementation notes
- Historical summaries and derived conclusions

## Goal

Keep memory concise, durable, and easy to apply, while using the knowledge base for the rich details.
